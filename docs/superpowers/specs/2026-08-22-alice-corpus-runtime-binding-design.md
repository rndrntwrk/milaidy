# Alice Corpus Runtime Binding Design

**Date:** 22 August 2026  
**Target runtime:** `rndrntwrk/milaidy` branch `release/alice-production-core-2026-08-22`  
**Corpus:** `ALICE_CORPUS_MASTER_v1.0`

## Goal

Bind the physically separated Alice corpus projections and their knowledge graph to the canonical Eliza runtime inside Milaidy without copying private corpus material into the repository, weakening projection isolation, or allowing knowledge to become action authority.

## Confirmed runtime contract

The production branch already has a native knowledge persistence path:

- `packages/agent/src/runtime/default-knowledge.ts` stores document memories in `documents` and retrieval fragments in `knowledge`.
- IDs are deterministic per agent, document key and fragment position.
- embeddings are generated by `runtime.addEmbeddingToMemory` when not supplied.
- seeding is idempotent and removes stale fragments within a known document.
- `packages/agent/src/runtime/eliza.ts` schedules bundled knowledge seeding after runtime startup when native knowledge is enabled.
- `packages/app-core/src/runtime/eliza.ts` already probes document and knowledge row counts after SQL compatibility bootstrap.

The corpus binding will use that persistence contract through a dedicated core plugin rather than hard-coding hundreds of private records into the Milaidy repository.

## Architecture

### 1. Dedicated core plugin

Create `@rndrntwrk/plugin-alice-corpus` under `plugins/plugin-alice-corpus` and add it to `CORE_PLUGINS`.

The plugin is always resolvable in the workspace but remains inert unless `ALICE_CORPUS_ROOT` is configured. This gives production an explicit mount contract while preserving ordinary Milaidy startup when no corpus is present.

### 2. External, immutable corpus root

The plugin reads an extracted corpus directory mounted into the runtime. It never requires source-vault files to be committed to GitHub.

Required files:

```text
CORPUS_MANIFEST.json
SHA256SUMS.txt
projections/<projection>/MANIFEST.json
projections/<projection>/records.jsonl
projections/<projection>/dossiers/*.md
projections/<projection>/graph-nodes.jsonl
projections/<projection>/graph-edges.jsonl
```

### 3. Explicit projection selection

Supported projections:

```text
public
internal
diligence
restricted-security
owner-private
```

`ALICE_CORPUS_PROJECTION` is mandatory whenever a corpus root is configured. There is no silent fallback from public to internal.

`owner-private` additionally requires `ALICE_CORPUS_ALLOW_OWNER_PRIVATE=1`.

The selected projection is a physical boundary. The loader reads only the selected projection directory and never filters the complete corpus at response time.

### 4. Fail-closed verification

Before ingestion, the plugin validates:

- the corpus root and selected projection remain inside the configured root;
- manifest structure and projection identity;
- the selected projection's declared record count;
- every selected input against `SHA256SUMS.txt` when a checksum entry exists;
- JSONL parseability and uniqueness of record, node and edge IDs;
- every graph edge endpoint exists in the selected node set;
- every loaded record visibility is admitted by the projection manifest;
- no secret-value file is read.

Verification modes:

```text
selected  # default; verify only files used by this runtime
full      # verify every path in SHA256SUMS.txt
off       # development only; prohibited in strict mode
```

### 5. Knowledge-document construction

The loader produces `DefaultKnowledgeDocumentDefinition[]` without modifying the corpus.

Dossiers become one document each. Their fragments are split by Markdown headings and bounded paragraphs.

Atomic records are grouped into stable documents by `record_type`. Each record becomes one fragment containing:

- title;
- statement;
- counterclaim or boundary;
- record ID;
- subject ID;
- truth class;
- authority class;
- canonicality;
- maturity;
- as-of date;
- claim permission;
- source references.

This keeps document count bounded while retaining record-level retrieval granularity.

All document keys include corpus version, projection and logical path. Metadata includes the corpus digest, projection, document kind and source path.

### 6. Idempotent projection reconciliation

After seeding, the plugin removes prior `alice-corpus` documents and their fragments when they are not part of the selected corpus version and projection.

This is essential when a runtime changes from `internal` to `public`: private fragments must be physically removed, not merely ignored by a response filter.

Default Milady knowledge is never removed.

### 7. Read-only graph index

The plugin loads the selected projection's `graph-nodes.jsonl` and `graph-edges.jsonl` into a bounded in-memory index. The current internal projection is small enough for this approach and it avoids opening the unrestricted full-corpus SQLite database in a public process.

Supported operations:

```text
search(query, nodeTypes?, limit?)
getNode(nodeId)
neighbors(nodeId, edgeTypes?, direction?, limit?)
shortestPath(source, target, edgeTypes?, maxDepth?)
findEvidence(nodeId, depth?)
listConflicts(limit?)
listGaps(limit?)
```

No graph operation writes to the corpus or to protocol systems.

### 8. Eliza actions

Expose explicit read-only actions:

```text
ALICE_GRAPH_SEARCH
ALICE_GRAPH_GET_NODE
ALICE_GRAPH_NEIGHBORS
ALICE_GRAPH_PATH
ALICE_GRAPH_FIND_EVIDENCE
ALICE_GRAPH_LIST_GAPS
```

Each result includes the corpus version, projection, node or edge identifiers and relevant record/source references. Actions are unavailable when the corpus is disabled or invalid.

### 9. Action-authority boundary

Corpus text, graph nodes, old conversation commands and procedures are knowledge only. They cannot:

- authorize a transfer;
- authorize a deployment;
- grant a tool;
- change a runtime capability;
- broaden a policy;
- send a message;
- alter a treasury or signer.

Consequential actions continue to require the active runtime programme, current capability, policy and approval system.

### 10. Configuration

```text
ALICE_CORPUS_ROOT=/absolute/path/ALICE_CORPUS_MASTER_v1.0
ALICE_CORPUS_PROJECTION=internal
ALICE_CORPUS_VERIFY=selected
ALICE_CORPUS_STRICT=1
ALICE_CORPUS_GRAPH_ENABLED=1
ALICE_CORPUS_ALLOW_OWNER_PRIVATE=0
```

`ALICE_CORPUS_ROOT` absent means the plugin is disabled. A configured but invalid corpus fails runtime initialization when strict mode is enabled.

### 11. Observability

Startup logs must report:

- corpus version;
- selected projection;
- verification mode;
- selected-input digest;
- dossier count;
- record count;
- generated document and fragment counts;
- graph node and edge counts;
- seeded, updated, retained and pruned memory counts;
- elapsed time.

No source text, private relationship data or secret values are logged.

### 12. Admission gates

The feature is admitted only when:

- parser and projection tests pass;
- checksum and path-traversal tests pass;
- owner-private gating tests pass;
- knowledge seeding is idempotent;
- projection switching removes prior private corpus rows;
- graph endpoints and query operations pass;
- public projection cannot retrieve internal fixture records;
- corpus text cannot grant action authority;
- package typecheck and build pass;
- the production runtime starts with the internal projection and reports expected counts;
- the public runtime starts separately with the public projection;
- no secret patterns appear in generated logs or fixtures.

## Non-goals

This change does not:

- commit the 82 MB corpus to the repository;
- make the graph the authority for chain, financial or deployment state;
- import the unrestricted full graph into public Alice;
- promote unresolved `UNKNOWN` records to facts;
- deploy a production container or mutate live corpus data;
- replace current Eliza memory, programme or capability controls.
